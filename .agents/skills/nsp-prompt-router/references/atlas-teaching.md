# Coordinated Atlas teaching

Read when a visual Atlas materially helps the question or the user asks to open it.
Berean is the semantic teacher; the browser is a deterministic local projection.

Keep one journey across follow-ups: question, intent, investigation/lesson/view/
tour IDs, snapshot identity, stable focus and relation IDs, EvidenceRefs, unresolved
terms, and next questions. Resolve “this” against that current journey. Do not
restart discovery on every turn or present Knowledge Graph and Code Map as separate
user products.

Author advisory AtlasViewSpec and optional GuidedTour from the same stable IDs and
snapshot cited in chat. Resolve every evidence reference and validate before opening.
Start `_nsp knowledge view --target <repo> --serve --view-spec-json <json>
--tour-json <json> --json` internally (omit the tour argument without a tour).
Return one directly clickable `http://127.0.0.1:<port>/atlas/<session-id>` link.
If a loopback session is unavailable, retain the validated artifact and state that
limitation; do not make a CLI command the user's primary opening mechanism.

For substantive follow-ups, send bounded focus/path/teaching-step/release cues
using the exact current IDs. Clear or omit a cue when IDs cannot resolve. Agent
emphasis remains temporary and distinct from human selection. Keep coordination
one-way, chat -> Atlas: browser hover, search, selection, filters, and navigation
are never messages, semantic facts, or authorization back to chat. Browser URL and
history state are local. Agent cues do not overwrite the learner's selections.

Distinguish current live preview from captured evidence. Stale snapshots or lessons
cannot silently become current. Repair mismatched IDs or invalid references before
handoff. Generic CLI, local MCP, and harness adapters are equivalent entry surfaces;
provider callbacks are optional conveniences, never evidence authority.
